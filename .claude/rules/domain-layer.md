# domain 層に何を置くか

`domain/` は「**抽出先**」ではない。何を置くかが決まっていないと、置けなかったものの集積所になる。

## 値オブジェクト（VO）

### 作る基準 / 作らない基準

| 状況 | 判断 |
|---|---|
| その型が存在する限り**必ず成り立つ不変条件**がある（負でない金額・空でない名前・形式が保証されたメール） | **作る** |
| **等価性が値で決まる**（ID ではなく中身で比較する） | 作る根拠になる |
| 同じ制約の組み合わせが**複数の場所で必要**になっている | 作る根拠になる |
| 単なる `string` / `int` に**名前を付けたいだけ** | **作らない**。型エイリアス・名前付き型で足りる |
| 制約が**その 1 箇所でしか意味を持たない** | **作らない**。呼び出し元のローカルな検証で足りる |

**最も重要な基準は「不変条件があるか」。** VO の価値は「**その型を持っている＝妥当である**」ことにあり、不変条件が無ければ型が何も保証しない。名前を付けたいだけなら VO にしない。

### VO の検証と、入口のスキーマ検証の関係

**この 2 つは役割が違うので両方必要。** どちらか一方に寄せない。

| | 入口のスキーマ | 値オブジェクト |
|---|---|---|
| 守る対象 | **信頼できない外部入力**（HTTP リクエスト） | **プログラム内部の誤り**（バッチ・別の usecase・テストからの生成） |
| 目的 | 400 系のエラーレスポンスを**統一形**で返す | その型を持つ値が**常に妥当**であることを保証する |
| 通らない経路 | HTTP を経由しない処理（バッチ・CLI・イベント受信） | — |

- **入口のスキーマ検証を、VO があるからと省略しない。** 信頼境界での防御とエラー形式の統一は入口の役割であり、VO では代替できない（VO の例外は HTTP のレスポンス形式を知らない）。
- **制約の定義は 1 箇所にする。** 同じ正規表現・閾値をスキーマと VO の両方に**書き写さない**。**VO を正本にして入口のスキーマがその生成関数を呼ぶ**か、**制約値を定数として共有**する。
- **VO を通した後は再検証しない。** usecase やドメインサービスで「メールに `@` が含まれるか」を書き直さない。型が保証している。

**これは `duplication.md` のフロント / バックエンドの例外条項と同じ構造である。** 信頼境界が違うので**実行**は重複してよいが、**定義**は 1 箇所に置く。

**`api.md` の担当レイヤ表との関係**: 表の「形式・構文 → 入口のスキーマ」は**検証を実行する担当**を定めたもの。VO は**その値がドメイン内部で妥当であり続けること**を担当する。**別の層の別の役割**であり、二重定義には当たらない。

## ドメインサービス

### 定義

**エンティティにも値オブジェクトにも置けない、複数のドメインオブジェクトにまたがる業務判断**を置く。

### usecase との違い

| | usecase | ドメインサービス |
|---|---|---|
| 担うもの | **ユースケース 1 つ分の手続き**（入力の受領 → 検証 → 永続化 → 副作用の順序） | **再利用される業務判断そのもの** |
| 持つもの | トランザクション境界・永続化の呼び出し・副作用 | **持たない**（純粋な判断） |
| 呼ばれ方 | 入口（controller / router / handler）から 1 回 | 複数の usecase・集約 Validator から |

**トランザクション・永続化・副作用を持ち込んだ時点で、それは usecase である。** ドメインサービスに `repository.save()` が現れたら、置き場所を間違えている。

### 集約 Validator はドメインサービスの一種

`dry-run.md` の**集約 Validator は、検証に特化したドメインサービス**である。別概念ではない。

- 複数の業務ルールにまたがる判断を持つ → ドメインサービスの定義に合致する
- 永続化・トランザクションを持たない → usecase ではない
- **両経路より下位（application 層以下）に置く**（`dry-run.md`「置き場所」）→ domain に置けばこの条件を満たす

### 受け皿にしない

- **1 つのエンティティ / VO に置けるなら、そこに置く。** ドメインサービスは「どこにも置けないもの」の集積所ではない（`duplication.md` の「`common` / `util` を置き場にしない」と同じ理由）。
- **名前が付けられないなら、切り出す単位が間違っている。** `TaskDomainService` のような「モデル名＋Service」は、たいてい**エンティティに置くべきメソッドの寄せ集め**になっている。

## レビュー観点

- VO に**不変条件が無く**、単に型名を付けただけになっていないか
- 同じ正規表現・閾値が、入口のスキーマと VO の**両方に書き写されて**いないか（実行の重複は可、**定義の重複は不可**）
- VO があることを理由に、**入口のスキーマ検証を省略**していないか
- VO を通した値に対して、usecase やドメインサービスで**同じ検証を再実行**していないか
- ドメインサービスが**トランザクション・永続化・副作用**を持っていないか（持っていたらそれは usecase）
- ドメインサービスが「置き場所に困ったもの」の集積になっていないか。名前が説明的すぎないか
